# Whilo Trace: design doc

Статус: 0.2.1, исправления счета потерь, начала потерь и отчета, 2026-11-07. Автор: Firat Baghirli (Whilo Labs).

## 1. Зачем

Программа для мониторинга сетевого пути: несколько целей одновременно, по каждой путь по хопам, потери и задержка на каждом хопе в реальном времени, таймлайн за окно от 5 минут до 24 часов, отчет для провайдера. По функциям ориентир PingPlotter, но код пишется с нуля (clean-room): бинарники PingPlotter не декомпилируются и не анализируются, его код, иконки, название и фирменный вид не копируются. Поведение изучено только по публичному мануалу и release notes.

Свое отличие от аналогов: программа сама отличает узел, который просто не отвечает на ICMP к себе, от настоящих потерь на пути, и показывает, с какого хопа потери начинаются.

## 2. Аналоги

| Проект | Лицензия | Windows без админа | Что взяли |
|---|---|---|---|
| Trippy (`trippy-core` 0.13) | Apache-2.0 | нет: на Windows нужен Administrator | идеи: раунд как набор проб по всем TTL, ECMP-стратегии на будущее |
| mtr | GPL-2.0 | только WSL или Cygwin, suid-root | формат статистики по хопу (loss, sent, last, avg, best, worst) |
| WinMTR | GPL-2.0 | да, ICMP API | подтверждение, что ICMP API с TTL работает без админа |
| NextTrace | GPL-3.0 | только ICMP | JSON-вывод, запись сессий |
| SmokePing | GPL-2.0 | серверный | «дымный» график: полоса min..max вокруг средней |
| PingPlotter 5 (коммерческий) | EULA запрещает реверс | да, ICMP API | только поведение из мануала: залп проб по TTL, окно статистики равно видимой части таймлайна, красные отметки потерь |

Код GPL-проектов не копируется, взяты только общеизвестные алгоритмы traceroute/MTR.

### Почему не `trippy-core`

- На Windows он требует права администратора (raw-сокеты), а без админа это требование MVP.
- Unprivileged-режим по его документации есть только на macOS.
- API помечен нестабильным.

Поэтому движок свой: на Windows `IcmpSendEcho2`, на Linux и macOS ICMP datagram-сокеты. `trippy-core` (Apache-2.0, совместим с MIT/Apache) можно подключить позже как дополнительный режим для UDP/TCP и Paris/Dublin-трассировки там, где есть права.

## 3. Стек

- Rust (stable 1.99), Cargo workspace.
- GUI: Tauri 2.12, фронтенд на чистом HTML/CSS/JS без сборщика и без `node_modules`, графики свои на inline SVG (картинка таймлайнов для отчета рисуется на canvas).
- SQLite через `rusqlite` 0.41 (bundled).
- CLI: `clap` 4.
- Обратный DNS: `dns-lookup` 4.
- Карта маршрута (раздел 10): d3-geo 3.1.1, d3-array 3.2.4 и topojson-client 3.1.0 (ISC) готовыми файлами в `app/ui/vendor`, суша Natural Earth, рисует canvas. База мест DB-IP Lite (CC BY 4.0) через `maxminddb` 0.32 (ISC) с memory map; обновление базы: `ureq` 3.5, `rustls` 0.23 с `ring`, корневые сертификаты системы через `rustls-platform-verifier`, распаковка `flate2`.

Один бинарник GUI и один CLI, общий движок. Workspace лежит внутри Obsidian-хранилища, поэтому сборка вынесена в скрытую папку `.target` (`.cargo/config.toml`): Obsidian не индексирует папки с точкой.

Поток данных: монитор цели шлет `RoundRecord` в колбэк. Ядро пишет раунд в SQLite, кладет в память (последние 25 ч на цель: окно 24 ч и запас) и в корзины открытых окон, потом шлет событие `round` в интерфейс. Интерфейс просит `snapshot` (окно, его конец или «сейчас», выделенный период, трасса цели) не чаще раза в секунду и только в живом режиме. Ядро отдает готовые корзины (средняя, min, max, потери, число проб и ответов) и цифры за окно и за период, статусы считает тоже ядро. Корзины лежат на неподвижной сетке: новый раунд меняет только свою корзину, поэтому снапшот стоит число корзин и хопов, а не раундов (окно 24 ч на 7 целях в release-сборке: около 0,1 мс после первого построения корзин, тест `day_of_seven_targets_is_quick`). Окно старше памяти читается из SQLite отдельным соединением и запоминается до смены окна.

## 5. Движок

Раунд: на каждый TTL от 1 до длины пути уходит одна ICMP echo-проба, все пробы раунда в полете одновременно, шаг между отправками 25 мс. Раунд ждет все ответы или таймаут. Следующий раунд стартует через интервал от начала предыдущего, даже если тот еще ждет ответы: раунды перекрываются, поэтому интервал 0,5 с держится при таймауте 2 с (проверено: 12 раундов за 6 с без админа). Раунды отдаются по порядку начала. Пауза останавливает отправку, поток и история остаются; интервал меняется со следующего раунда.

- Длина пути: TTL, на котором ответила цель. Пробы дальше цели не шлются. Если самая глубокая проба истекла в пути (маршрут удлинился), следующий раунд снова идет до 30, а сам этот раунд не считается: он не мог дойти до цели и о потерях ничего не говорит.
- Если цель не ответила 5 раундов подряд и длина пути известна, раз в минуту раунд идет до 30: маршрут мог удлиниться за роутером, который молчит, и по раунду до старой длины этого не узнать. Цена: около 20 лишних проб в минуту на такую цель; раунд на (30 - длина)×25 мс дольше обычного. После одного потерянного раунда полный не идет: он доходит до цели любой из проб дальше нее, и потери читались бы ниже настоящих (в модели с независимыми потерями при интервале 60 с 21,7 % вместо 30 %). Пока длина неизвестна (цель не отвечала с запуска или сменился адрес), каждый раунд идет до 30, как и раньше.
- Если цель не ответила, слот цели остается в раунде как потеря, а сам раунд хранится до одного молчащего хопа после последнего ответившего: дальше ответов нет. Как такой раунд считается на хопах дальше, в разделе 6.
- Ответ «цель недоступна» (ICMP Destination Unreachable) заканчивает раунд на приславшем его роутере, пробы дальше не хранятся.
- RTT меряется своим таймером от вызова отправки до события ответа: ICMP API отдает только целые миллисекунды.
- Имя цели резолвится раз в 5 минут, смена IP сбрасывает длину пути.
- Программа работает в одном экземпляре (`tauri-plugin-single-instance`): второй запуск поднимает окно первого, иначе цели опрашивались бы вдвое. Режим имитации сюда не входит, он сети не касается. Командная строка своими целями главный экран не меняет: `watch` заводит новую цель как убранную и не трогает существующие.
- Только IPv4. IPv6 (`Icmp6SendEcho2`, ICMPv6 dgram) в планах.

| Параметр | Whilo Trace | PingPlotter (по мануалу) |
|---|---|---|
| Тип пробы | ICMP echo через системный API | ICMP через Windows DLL |
| Интервал | 2.5 с | не найден, в гайдах 2.5 с |
| Таймаут | 2 с (должен быть меньше интервала) | 3 с, меньше 1 с дает ложные потери |
| Шаг между пробами | 25 мс | около 25 мс |
| Данные пробы | 32 байта | пакет 56 байт |
| Максимум TTL | 30 | не найден (legacy: 35) |

Проверено на Windows 11 без админа: хопы и цель находятся, параллельная отправка 9 TTL занимает время одного таймаута вместо суммы.

## 6. Классификация хопов

Статистика считается по окну (по умолчанию окно таймлайна): sent, recv, loss %, last, avg, min, max, jitter (среднее модуля разности соседних RTT).

Раунд, который не дошел до цели, хранит пробы только до места, где кончился, но пробы на хопы оттуда до цели тоже ушли и ответа не получили. Поэтому при подсчете он идет как отправленный и потерянный на каждом таком хопе (потеря на пути), и строка цели в трассе видит те же потерянные раунды, что строка цели на главном экране. Цель для этого счета: TTL, на котором чаще всего кончаются дошедшие до нее раунды периода, а если таких нет, то раунды всего окна, а если и таких нет, то ближайший дошедший раунд к тому же адресу не дальше суток (сначала до окна, потом после). Только если и его нет, хоп считает лишь раунды, где есть его проба. Так считают движок (`lost_past_end` в `crates/engine/src/stats.rs`) и корзины ядра (`crates/store/src/buckets.rs`, тест `buckets_match_the_engine_when_rounds_end_early`). Хранение от этого не меняется, поэтому так же считается и история, записанная версией 0.1.0.

Потом каждому хопу ставится статус:

| Статус | Правило | Что значит |
|---|---|---|
| `silent` | ни одного ответа, но дальше по пути кто-то отвечает | узел не отвечает на ICMP к себе, трафик пропускает; не потеря |
| `rate_limited` | потери от 2%, но минимальные потери дальше меньше на `max(2%, половина потерь хопа)` | узел ограничивает свои ICMP-ответы; не потеря |
| `lossy` | потери от 2%, и они продолжаются дальше | настоящие потери |
| `no_reply` | не отвечает ни он, ни кто-то дальше | путь обрывается или цель молчит |
| `unreachable` | ответы «цель недоступна» не меньше 2% проб хопа, и это не цель | путь к цели обрывается на этом роутере |
| `ok` | потери меньше 2% | норма |

Начало потерь: если цель `lossy`, идем от цели назад. Цепочка продолжается через `lossy` и `unreachable` (роутер, на котором обрываются раунды); `silent` и `rate_limited` пропускаются: их собственные неответы ничего не говорят о пути, и таких хопов началом не называем; на любом другом статусе обход останавливается. Самый ранний `lossy` или `unreachable` цепочки помечается «loss starts here» и попадает в вывод отчета; если таких нет, потери появляются только на цели. Если перед целью стоят только `rate_limited` (и `silent`), начало потерь не называем: это нельзя определить по хопам. Роутер, который ограничивает ответы, не становится началом и не получает вины за потери дальше него.

Строки за целью (раунд нашел цель глубже обычного) в сравнении «потери продолжаются дальше» не участвуют: в них только немногие раунды, дошедшие так далеко, и нет потерянных, поэтому их низкие потери не значат, что потери кончились. В строке цели проба на ее TTL, потерянная в раунде, который все же дошел до цели глубже, не считается отправленной: цель в этом раунде ответила.

Цель трассы: TTL, на котором чаще всего кончаются раунды, дошедшие до цели, а если таких нет, то все раунды. Строка на этом TTL считается целью, если там ответила сама цель или не ответил никто. Строка, где отвечали только роутеры (например, «цель недоступна»), целью не считается: выводы говорят, что цель не отвечает и этот хоп сообщает, что она недоступна. На строке цели ответ «цель недоступна» от роутера перед ней считается потерей. Потери до цели в вердикте и выводах считаются по раундам, как в строке цели на главном экране.

В версии 0.1.0 хоп считал только раунды, где есть его проба, и раунды, оборвавшиеся раньше, для хопов дальше пропадали: потери на пути выглядели как «отвечает не на все пробы», а роутер с ответом «цель недоступна» считался целью в норме. Найдено режимом имитации (`crates/engine/src/sim.rs`) 2026-10-28, исправлено подсчетом при чтении (выше).

Проверено на живой линии: шлюз VPN не отвечает совсем (`silent`), промежуточный роутер теряет половину своих ответов при чистых хопах дальше (`rate_limited`). Ни то, ни другое не выглядит обрывом.

## 7. Хранение

SQLite в `%LOCALAPPDATA%\Whilo Trace\history.db` (Linux: `$XDG_DATA_HOME/whilo-trace` или `~/.local/share/whilo-trace`, macOS: `~/Library/Application Support/Whilo Trace`), общий для GUI и CLI, WAL, ожидание чужой записи до 5 с.

Схема версии 1:

```
targets(id, host UNIQUE, active, created_ms, position, interval_ms, paused, probe)
rounds(id, target_id, ts_ms, dst, path_len, reached, probe)     индекс (target_id, ts_ms)
hops(round_id, ttl, kind, addr, rtt_us)                          WITHOUT ROWID
pinned(id, target_id, ttl, probe, addr, position, created_ms)    UNIQUE (target_id, ttl, probe)
settings(key, value)                                             значение в JSON
recent(host COLLATE NOCASE, used_ms)                             последние 10 вводов
```

- Цели и вынесенные хопы стоят в одном порядке главного экрана (`position`). У цели свои интервал, пауза и тип пробы, у каждого раунда тип пробы, с которым он отправлен.
- Убранная цель остается в `targets` с `active = 0` вместе с раундами, ее вынесенные хопы удаляются. Добавленная снова, она получает прежний id и свою историю.
- Миграция: версия схемы в `PRAGMA user_version`. Версия 0 это таблицы прототипа (коммит `0484d8f`), новая база проходит те же шаги. Версия 1 добавляет столбцы через `ALTER TABLE ... ADD COLUMN` со значениями по умолчанию (старые строки не переписываются, на большой истории это быстро) и новые таблицы. Все идет в одной транзакции `BEGIN IMMEDIATE`: второй процесс со старым файлом ждет и находит работу сделанной. История прототипа не теряется (тест `migrates_an_old_database_without_losing_history`).

Хранятся сырые пробы, все метрики считаются по окну. Объем: при 10 хопах и интервале 2.5 с около 345 тыс. строк `hops` в сутки на цель, порядка 10-15 МБ. Политика хранения и прореживание старых данных: позже.

## 8. Интерфейс

Два экрана, оба обновляются вживую (не чаще раза в секунду) и не теряют наведение, меню, выделение и прокрутку. Тема по системе или своя, язык русский или английский; плоский стиль без рамок и теней, красный только для потерь, статусы нейтральные, пояснения только в подсказках.

- **Все цели.** Шапка: поле цели с недавними вводами, типы проб (сейчас работает только ICMP, остальные видны выключенными), интервал новой цели, окно от 5 минут до 24 часов, легенда, настройки карточкой справа (пороги задержки, тема, язык, база мест карты маршрута). Сводка: строка на цель и на каждый вынесенный хоп, потери, средняя, минимум, текущая задержка, мини-график; пауза, убрать, открыть трассу. Стопка таймлайнов: линия задержки на фоне по порогам, сплошной красный столбец потери, янтарные отметки, когда хоп отвечает не на все пробы, штриховка, когда хоп не отвечает на пробы этого типа, полоса jitter, подсказка по наведению. Выделение участка мышью пересчитывает сводку за период. Порядок строк сводки и таймлайнов один, меняется перетаскиванием и сохраняется. Внизу полоса истории за сутки с отметками потерь: щелчок или перетаскивание рамки открывает прошлое, стрелки листают сутки, плашка показывает, что на экране прошлое.
- **Трасса цели.** Выводы простым текстом (где начинаются потери, какие хопы не отвечают, какой роутер сообщает, что цель недоступна), таблица хопов со статусами и полосой задержки, таймлайн выбранного хопа с полосой цели под ним; выделение участка пересчитывает таблицу хопов за период. Любой хоп выносится на главный экран отдельным таймлайном. У цели свои интервал и пауза. Карточка хопов переключается между таблицей и картой маршрута (раздел 10).
- **Отчет для провайдера.** Диалог: строки, период (как на экране, выделенный, 1 ч, 6 ч, 24 ч, свой), часовой пояс, форматы, выводы, папка (раздел 9).
- Первый запуск: пустой экран с быстрыми кнопками целей. Ядро не ответило: спокойное сообщение и повтор, а не пустой экран.

Код интерфейса устроен по частям (`ui/parts`), данные приходят снапшотом ядра (`docs/ui-contract.md`). В обычном браузере интерфейс работает на заглушке ядра (`ui/base/mock.js`, флаги `?mock=strict`, `?mock=live`, `?mock=empty`, `?mock=down`; флаги карты в разделе 10), так его можно делать и проверять без сборки Rust.

Программу целиком (ядро, база, движок) можно проверять без сети на имитации в движке (`crates/engine/src/sim.rs`). Если `WHILO_TRACE_SIMULATE` задана любым значением, кроме `0`, `false`, `no` и `off`, ядро берет оттуда пробы, резолв имен и обратный DNS (все три через один объект `Net`), так что программа не шлет ни одной пробы и ни одного DNS-запроса. История пишется в отдельный `history-sim.db`, заголовок окна и каждый сохраненный отчет говорят, что сеть имитирована. Командная строка имитацию не знает. Слово в имени цели, целая часть имени между точками или дефисами, выбирает сценарий: `loss` (потери на пути с 7-го хопа: четверть раундов теряется оттуда до цели), `flaky` (потери на пути с 3-го хопа 70 секунд из каждых 5 минут), `down` (цель не отвечает), `unreachable` (роутер сообщает, что цель недоступна), `silent` (хоп не отвечает), `limit` (роутер отвечает на часть проб), `far` (длинный путь), `jitter` (всплески задержки с какого-то хопа). Остальные имена и адреса получают свою смесь, одинаковую от запуска к запуску; адреса домашней сети в одном хопе. Потеря на пути и всплеск задержки берут весь раунд со своего хопа, как перегрузка канала. Все выдуманные адреса из диапазонов для документации, тестов, частных сетей и провайдерского NAT.

Что раздражало в UI PingPlotter: таймлайны нельзя переставить без удаления и добавления заново. Здесь порядок меняется перетаскиванием.

## 9. Экспорт

Диалог «Отчет для провайдера» (период, строки, форматы, часовой пояс, выводы) вызывает `export_report`. Период полуоткрытый, `[с, по)`, как окно таймлайна. Ядро создает новую папку `<имя>-<ГГГГММДД-ЧЧММСС>` в выбранной папке или в `Documents\Whilo Trace\`: имя это адрес цели, если все строки от одной цели, иначе `whilo-trace`; время это конец периода в выбранном поясе. Готовая папка не перезаписывается, следующая получает `-2`, `-3`. Команда возвращает путь к новой папке; интерфейс показывает его и открывает папку или `report.html` через `open_folder` (она открывает только папку или файл отчета).

- `report.html`: самодостаточная страница на языке интерфейса: период и пояс, выводы из диалога (если в диалоге их нет, то и в отчете нет), по каждой цели SVG-таймлайн цели и вынесенных хопов, таблица хопов, метод. Статусы нейтральные, как в интерфейсе, тип пробы берется из данных («не отвечает на ICMP»).
- `timeline.png`: картинка таймлайнов, как на экране; ее рисует интерфейс.
- За период, где ни один раунд не дошел до цели, таблица и таймлайны вынесенных хопов считают цель по ближайшему дошедшему раунду к тому же адресу не дальше суток (сначала до периода, потом после), как и экран для такого окна. Выводы диалога за выделенный или свой период берут начало потерь и статусы хопов из этого же периода (`rangePath`). Вынесенный хоп в `report.html` красит только потери на пути; неответы при ответившей цели идут янтарной меткой снизу, у молчащего хопа меток нет, как на экране. Конец периода не позже времени создания отчета (живое окно кончается концом корзины, позже текущего момента); интервал в строке метода считается по раундам периода (медиана).
- `hops.csv`: таблицы хопов всех целей; `samples.csv`: каждая хранимая проба (цель, время UTC, тип пробы, TTL, тип ответа, адрес, RTT); раунд без ответа цели кончается молчащим хопом или роутером с ответом «цель недоступна» (раздел 5).
- `report.json`: все то же в машинном виде, время в UTC, выводы из диалога.
- `map.png`: карта маршрута, только в отчете с экрана трассы и когда у маршрута есть места, при любом наборе форматов. Ее рисует интерфейс в момент сохранения по данным экрана трассы (его окно или выделенный на нем период, а не период отчета): раскладка 1200×675 с лентой хопов справа, файл вдвое крупнее (2400×1350 пикселей), светлая и без маскировки (отчет для провайдера), в виде карты по умолчанию, а не в масштабе, выбранном на экране. Та же картинка встроена в `report.html` блоком «Карта маршрута» над графиками, с подписью `IP Geolocation by DB-IP (https://db-ip.com), CC BY 4.0` в подвале, так что страница остается одним файлом.

`whilo-trace-cli report <host> --last 1h --out reports` пишет отчет по одной цели из сохраненной истории прямо в папку `--out`: `<host>-<время>.html`, `-hops.csv`, `-samples.csv`, `.json`. Он на английском и с выводами самого движка: у командной строки нет диалога.

## 10. Карта маршрута

Карточка хопов на экране трассы переключается между таблицей и картой («Таблица / Карта», в адресе `?view=map`). Карта рисует путь от дома до цели на карте мира в проекции Equal Earth, повернутой к маршруту, с номерами хопов как в таблице; выбранный хоп показывает свое место, AS и проверку скоростью света. Карту можно приближать и двигать, а маршрут через океан открывается на основном участке с указателем на остальное (ниже, «Вид, масштаб и длинный маршрут»). По маршруту бежит пакет настоящих раундов цели, карточку с картой можно развернуть во весь экран (ниже, «Пакет и полный экран»), «Сохранить картинку» делает картинку для публикации. Код: `crates/geo` (места и проверка), `app/src/geo.rs` (снапшот и команды), `app/ui/parts/map/` (вид, диалог базы, картинка); команды и поля в `docs/ui-contract.md`.

### Данные

- База мест: DB-IP IP to City Lite и IP to ASN Lite, файлы MMDB под CC BY 4.0 (подпись «IP Geolocation by DB-IP» со ссылкой на https://db-ip.com). Распакованные базы за октябрь 2026 по странице DB-IP: 121,1 МБ и 9,1 МБ. Названия стран есть на русском и английском, городов и регионов только на английском. Поля точности (accuracy radius) в Lite нет, поэтому уровень места берется из того, какие поля есть: город с координатами, только страна или ничего.
- Встроенная база лежит среди ресурсов программы в папке `geo`: `dbip-city-lite.mmdb`, `dbip-asn-lite.mmdb`, `manifest.json` (месяц, размер и SHA-1 файлов), `NOTICE.txt` (подпись и лицензия). Папку готовит `tools/fetch_geo.py` на стандартной библиотеке Python: скачивает оба `.mmdb.gz` текущего месяца по UTC (если DB-IP его еще не выложила и отвечает 404, то предыдущего), распаковывает, проверяет метку метаданных MMDB и `database_type` (City и ASN), пишет каждый файл под временным именем и переименовывает в конце. `--self-test` проверяет чтение метаданных, месяцы и прогон целиком на маленьких базах в памяти, с подменой сети.
- База попадает в установщики и portable zip только в релизе: job `geo` в `.github/workflows/release.yml` скачивает ее один раз, так что у трех систем один месяц, и сборки идут с `tauri build --config tauri.geo.conf.json`. Этот конфиг добавляет в ресурсы `THIRD-PARTY-NOTICES.txt` и четыре файла из `.target/geo` в папку `geo`, каждый поименно: без любого из них tauri-build останавливает сборку (`ResourcePathNotFound`; пустую папку, указанную целиком, он пропустил бы молча), а лишний файл в папке, например `.tmp` от прерванного `fetch_geo.py`, в программу не попадет. Обычные `cargo build`, `cargo test` и CI собираются без базы: `bundle.resources` в основном конфиге ломал бы сборку, когда файлов нет. Месяц базы релиза дописывается в release notes.
- Встроенную базу программа ищет в `WHILO_TRACE_GEO_DIR`, если переменная задана (копия разработчика: на Linux и macOS сборка из `.target` ресурсов не находит), иначе в `geo` среди ресурсов, а если папку ресурсов узнать не удалось, в `geo` рядом с `history.db`. На Windows ресурсы лежат рядом с exe, и в установленной программе, и в portable.
- Подложка: суша Natural Earth 1:110m из world-atlas 2.0.2 (`ui/vendor/land-110m.js`) и точки подписей стран Natural Earth 1:10m (`ui/vendor/countries.js`, их делает `tools/ne_countries.py`), public domain. Границ стран на карте нет, страна только в подписи. Проекция и дуги по большому кругу через d3-geo.
- Места ищутся только в локальных файлах: при поиске места адрес хопа никуда не уходит (имена хопов, как и до карты, дает обратный DNS, который спрашивает о каждом адресе DNS-сервер системы). Специальные диапазоны IANA не ищутся: частные, CGNAT, loopback и link-local это «ваша сеть», они рисуются у дома (без дома у первого известного места); прочие специальные (документация, бенчмарки, multicast, зарезервированные) остаются без места.
- Имитация сети (`WHILO_TRACE_SIMULATE`) берет выдуманные места из `fake.rs`, одинаковые от запуска к запуску: провайдер в Баку, как в утвержденном макете, цель в городе, до которого свет в волокне успевает за ее RTT без шума, транзитные роутеры по дороге к ней; все эти места проходят проверку скоростью света. Исключение: набранные как есть 8.8.8.8 и 8.8.4.4 стоят в Mountain View, а 1.1.1.1 и 1.0.0.1 в San Francisco, там, где их ставят настоящие базы, близко это или нет, и проверка может их отметить (у 8.8.8.8 вердикт не «норма», это проверяет тест в `fake.rs`). Запросов в сеть нет.
- Заглушка интерфейса (`ui/base/mock.js`) отдает маршрут Баку - 8.8.8.8 с местами; с `?mock=live` каждый пятый раунд этой строки теряется с 7-го хопа. Строка www.upwork.com получает длинный маршрут Баку - Тбилиси - Стамбул - Франкфурт - Лондон - Нью-Йорк - Ашберн (цель в Ашберне, все места проходят проверку скоростью света от Баку, потери с 9-го хопа, Нью-Йорка): на нем видно основной участок и указатель на дальний (ниже, «Вид, масштаб и длинный маршрут»). Флаги `?mock=geo-new` (вышел новый месяц), `geo-none` (базы нет), `geo-broken` (база не читается) и `calm` (система просит меньше движения, карта открывается без пакета) пишутся через запятую с остальными.

### Крейт `crates/geo`

`whilo-trace-geo`: чистый Rust без Tauri, поэтому его тесты идут в CI на всех трех системах.

- `special.rs`: классы специальных адресов IPv4 и IPv6, адрес IPv4-mapped по правилам IPv4.
- `physics.rs`: расстояние по большому кругу (R = 6371 км), минимальный RTT в волокне и в вакууме, вердикт.
- `db.rs`: обе базы через memory map (`maxminddb` 0.32 с `mmap`): 130 МБ остаются на диске, читаются только страницы, которые нужны поиску. Тип базы проверяется по `database_type`.
- `locate.rs`: трейт `Locate` (место и AS адреса); его реализуют базы, выдуманные места и таблицы в тестах.
- `enrich.rs`: чистая функция над `Locate` для одной трассы: уровни мест, дом, расстояния и вердикты. Ядро вызывает ее в `Core::snapshot` после цикла по целям, когда данные целей уже не заблокированы.
- `fake.rs`: места для имитации из RTT модели пути без шума (`sim::model_rtts` в движке).
- `files.rs`: две папки, которые никогда не совпадают: встроенная `geo` и скачанная `geo-update` в папке данных рядом с `history.db`. Там же `manifest.json`, `state.json`, выбор набора (новее месяц, при равенстве скачанный) и уборка старых месяцев.
- `update.rs`: проверка нового месяца и скачивание (ниже).

### Проверка скоростью света

- Дом: первый по TTL хоп с уровнем «город», кроме цели и хопа, который ответил адресом цели. Или точка, заданная вручную: правый щелчок по карте, «Дом здесь», округление до 0,1°; «Сбросить дом» возвращает автоматический.
- Для каждого хопа с городом: расстояние d от дома и минимальный RTT 2·d/v. В вакууме v = 299 792,458 км/с, это около d/149,9 мс; в волокне v = c/1,5, около d/99,93 мс. Сравнивается минимум RTT хопа за окно (`stats.min`), не за выделенный период.
- Вердикт с допуском 1 мс (дом известен с точностью до города, у таймера свой шаг): «невозможно», если RTT + 1 мс меньше минимума в вакууме; «сомнительно», если меньше минимума в волокне; иначе «норма», и лишняя задержка = RTT минус минимум в волокне. У хопа дома расстояние 0 и «норма». Хопы «только страна», «ваша сеть» и без места не проверяются.
- Пример: Баку - Франкфурт около 3350 км, минимум в волокне около 33,5 мс, в вакууме около 22,4 мс; ответ за 52,4 мс проходит, лишняя задержка около 18,9 мс.
- Проверка ловит только грубые ошибки: anycast-адреса и роутеры, которые база ставит за тысячи километров от того, куда успевает свет. Место, прошедшее проверку, возможно, но не подтверждено.

### Обновление базы

- DB-IP выкладывает Lite раз в месяц, по их FAQ обычно 1-го числа, под именами с месяцем: `dbip-city-lite-ГГГГ-ММ.mmdb.gz` и `dbip-asn-lite-ГГГГ-ММ.mmdb.gz` на `https://download.db-ip.com/free/`.
- Проверка (`geo_check`) идет, когда экран трассы впервые показывает карту: один раз за загрузку страницы трассы и только с включенной настройкой «Проверять новую базу мест» (`geoCheck`, в блоке «База мест» настроек главного экрана). Без запроса: в имитации, с выключенной настройкой, если сегодня уже было предложение или запрос к серверу, удачный или нет (локальные даты в `geo-update/state.json`), и пока месяц открытой базы не старше текущего по UTC (база, которая не открывается, считается отсутствующей). Иначе один HEAD файла City текущего месяца (на ответ 405 или 501 GET с `Range: bytes=0-0`). День проверки пишется в `state.json` до запроса, поэтому неудачная проверка (нет сети, таймаут, ошибка HTTP, кроме 404) и проверка, прерванная закрытием программы, тоже занимают день: до конца дня `geo_check` отвечает `cached` и запросов не шлет, на следующий день проверка пойдет снова. Если `state.json` не записался, следующий вызов спросит снова. Таймауты: соединение 15 с, чтение 30 с, вся проверка 20 с.
- Если месяц вышел (`reason: "offer"`), интерфейс показывает диалог «Вышла новая база мест»: месяц, размер, если сервер его назвал (сжатый City и около 5 МБ на ASN), кнопки «Обновить» и «Пропустить» (фокус сначала на «Пропустить», Esc тоже пропускает). Когда базы нет или она не читается, диалог называется «Нужна база мест», а кнопка «Скачать». При других `reason` ничего не показывается. Если в этот момент открыт другой диалог (отчет, картинка), предложение ждет и открывается, когда тот закроется: ядро уже засчитало его за день. Во время скачивания в диалоге полоса и мегабайты из события `geo` и кнопка «Отменить» (`geo_cancel`, диалог закрывается сразу); после `done` он 2 с пишет «База мест обновлена» и закрывается, а страница сразу просит новый снапшот с новым месяцем; при ошибке в нем ее текст и «Закрыть». В диалоге «Нужна база мест» ошибки сети, HTTP и `geo_invalid` кончаются словами «Карта пока без мест.», а не словами о том, что база осталась прежней.
- Скачивание (`geo_download`) идет только после согласия: оба файла потоком через gunzip в `.part`, каждый открывается и проверяется по типу, потом переименовывается, `manifest.json` пишется последним. Прогресс приходит событием `geo` не чаще раза в 250 мс, отмена проверяется между чтениями, лимиты 512 МиБ сжатого и 1 ГиБ распакованного.
- Скачанная база ложится в `geo-update` с месяцем в именах файлов; во встроенную папку программа не пишет никогда. После скачивания старый ридер закрывается, выбирается новый набор, старые месяцы удаляются; открытый mmap-файл Windows удалить не дает, тогда он уходит при следующем запуске. «Удалить скачанную» (`geo_remove`) удаляет скачанные базы и оставляет `state.json`: обновление, предложенное сегодня, сегодня снова не предлагается.
- Блок «База мест» в настройках главного экрана: «Проверять новую базу мест» (Вкл / Выкл, `geoCheck`); строка «Сейчас: встроенная, октябрь 2026» (или «скачанная, ...», «нет», «не читается», «имитация»; во время скачивания к ней добавляются месяц и процент); кнопка «Удалить скачанную», только когда база скачанная; подпись «IP Geolocation by DB-IP (db-ip.com), CC BY 4.0; суша: Natural Earth».
- Сеть: `ureq` 3.5 с `rustls` и `ring`, корневые сертификаты из системы через `rustls-platform-verifier`, прокси из переменных окружения, User-Agent `Whilo-Trace/<версия> (+https://github.com/Whilo-Labs/whilo-trace)`.

### Вид, масштаб и длинный маршрут

- Высота: карточка с картой кончается у нижнего края окна, пока страница прокручена к началу. Сколько места под ней, считает `map.js` по тому, где начинается сцена (под выводами, сколько бы строк они ни заняли), и отдает в `--mp-h`; `map.css` держит сцену в пределах 354-694 px. При окне 1320×860 и двух строках выводов (строка upwork заглушки) это 639 px, и лента хопов показывает все 11 хопов при любом выбранном хопе; при четырех строках (строка google) 592 px, и когда выбран хоп со шкалой физики, лента прокручивается на 15-45 px.
- Узкая карточка (уже 1100 px): карта во всю ширину (320-640 px высотой, тоже до края окна), выбранный хоп и лента хопов под ней рядом, уже 820 px друг под другом. Во весь экран на узкой карточке карта оставляет нижние 160 px окна верху панели и ленты: колесо над ними прокручивает их, над картой масштабирует.
- Масштаб: «+» и «−» справа внизу карты, слева от них «Вписать маршрут» (у длинного маршрута вместо нее переключатель «Основной участок / Весь маршрут»); Ctrl + колесо вокруг указателя, не больше 2× за одно событие (простое колесо прокручивает страницу и на 1,5 с показывает «Ctrl + колесо: масштаб», во весь экран простое колесо масштабирует); двойной щелчок приближает в 2× в этой точке; с фокусом на карте клавиши «+», «−» и «0» (вписать). Перетаскивание от 4 px двигает карту, более короткое нажатие остается щелчком, а щелчок, которым кончилось перетаскивание, хоп не выбирает. Меню правого щелчка («Дом здесь») прежнее. На картинке кнопок нет.
- Пределы: отдаление до всего маршрута; приближение до 6× вида по умолчанию, но не уже 300 км по ширине карты (ближе суша 1:110m слишком грубая); при перетаскивании рамка всего маршрута остается в виде хотя бы на 30 % (меньшая рамка целиком) внутри отступа 40 px. «+» и «−» на пределах неактивны.
- Вид пользователя держится, пока идут живые данные, и возвращается к виду по умолчанию, когда меняются места маршрута (другая цель, новые места), и по «Вписать маршрут» или «0». Хоп, выбранный в ленте, таблице или клавишами, которого в этом виде не видно (за краем, у самого края или под табло, легендой, масштабом или кнопками), карта сдвигает внутрь полей, которые вид по умолчанию оставляет маршруту, на сколько нужно до них.
- Выноски, шаг сетки (10, 5, 2 или 1°), подписи градусов, масштаб и указатели у края пересчитываются для каждого вида; сетка и кресты рисуются только в видимой части. Пакет бежит в любом виде. Кадры через rAF, цикла кадров, пока ничего не движется, нет.
- Длинный маршрут: между двумя местами подряд больше 4500 км (океан). Если в виде всего маршрута его основной участок (от дома до последнего места перед скачком) занял бы меньше трети ширины и высоты карты, а мест на нем, разнесенных хотя бы на 12 px, не меньше трех, вид по умолчанию это основной участок, с полем 30 % с той стороны, куда уходит остальное. Иначе вписан весь маршрут. Пороги подобраны на 14 выдуманных маршрутах и записаны в комментарии `map-geo.js`: Баку - Франкфурт (3370 км) и Нью-Йорк - Лос-Анджелес (3940 км) остаются одним видом, а с 3000 км маршрут Баку - Франкфурт - Лондон - Нью-Йорк открывался бы на одном Баку; океан начинается примерно с 5000 км.
- Дальний участок сворачивается в указатель у края, пока на виде нет ни одного его места (вид по умолчанию, приближение к основному участку): пунктир от последнего хопа основного участка по большому кругу, стрелка и выноска с номерами хопов (больше трех: первый, выбранный и последний, между ними черточка), «→ город, страна» первого места по базе, «около N км от хопа K» и, если они там, начало потерь и цель с невозможным местом. Если выноске не хватает места, остаются номера и страна. Вид, на котором есть место дальнего участка (весь маршрут, приближение к нему), рисует маршрут как есть. Указатель цели с невозможным местом в дальнем участке своего не имеет и идет в эту выноску; если оба указателя уходят в одну сторону (в пределах 35° и 90 px), они сливаются.
- Пакет на дальнем участке ждет у стрелки, там же крест потерянного раунда и остановка ответа цели. Выбор хопа дальнего участка в виде по умолчанию карту не двигает: за него стоит выноска у края.
- Картинка для публикации и карта отчета рисуются всегда в виде по умолчанию (у длинного маршрута основной участок с указателем), какой бы масштаб ни был на экране.

### Пакет и полный экран

- Пакет идет по настоящим раундам цели на экране: событие `round` с ее `targetId` отмечает раунд, а первый снапшот, запрошенный после него, дает исход. Пакет доходит до цели, а если последний раунд цели потерян, останавливается на первом хопе хвоста хопов, у которых потерян последний раунд (молчащие хопы пропускаются, как в правиле начала потерь).
- В пути один пакет. Раунд, кончившийся за это время, ждет своей очереди, а более новый занимает его место, так что при коротком интервале часть раундов пакета не получает.
- Часы пакета: минимум RTT каждого хопа за окно, у хопов без него значение между соседями, и время только растет. Путь до цели занимает 2,4 с; при RTT цели меньше 8 мс он короче, больше 300 мс длиннее (от 0,008 до 0,3 с на миллисекунду). За пакетом след из пяти квадратов. Потерянный раунд оставляет красный крест на 1,5 с, ответ цели держится 0,7 с. Не больше 30 кадров в секунду, а когда ничего не движется, цикла кадров нет.
- Табло слева сверху: номер раунда, где пакет («хоп 3 → 4», RTT) и исход («ответ цели», «потеря на хопе 7»); между пакетами на нем исход последнего, а до первого «пакет ждет следующий раунд». В ленте хопов подсвечен хоп, где пакет. Номер первого пакета равен числу раундов окна, дальше он растет на число раундов, о которых ядро сообщило с прошлого пакета, так что смена окна его не сбивает; при смене строки цели (другой тип пробы) отсчет и пакеты начинаются заново.
- Пакета нет, маршрут показан целиком, а табло говорит почему: нажата «Пауза анимации», выделен период, цель на паузе или система просит меньше движения (`prefers-reduced-motion`: карта открывается на паузе; включение этой настройки ставит паузу, выключение снимает только паузу, поставленную системой). Раунды за это время не копятся. В виде «Таблица» карты нет, и пакета тоже.
- Пока карту не видно (прокручена за край окна, страница скрыта, окно свернуто), цикл кадров стоит; часы пакета идут, и снова видимая карта рисует текущий момент. Свернутое окно WebView2, возможно, считает видимым (не проверено), поэтому в программе, пока движется пакет, карта не чаще раза в секунду спрашивает окно Tauri (`isMinimized`), а пока оно свернуто, спрашивает раз в секунду и кадров не рисует.
- «Во весь экран» растягивает карточку хопов с картой на все окно, всегда в темной теме, и диалоги поверх нее тоже темные (`data-theme="dark"` на `#modal`); остальной экран трассы под карточкой получает `inert`, так что Tab и программы чтения с экрана остаются на карточке. В программе и само окно уходит в полноэкранный режим (`setFullscreen`, разрешение `core:window:allow-set-fullscreen` в `app/capabilities/default.json`). Обратно: «Выйти из полного экрана», Esc (если нет перетаскивания, открытого меню или диалога) или переключение на «Таблицу»; режим кончается и сам, вместе с полноэкранным окном, когда карточки с картой не стало (например, в окне не осталось раундов или цели больше нет); уход со страницы тоже снимает полноэкранный режим окна.

### Маскировка картинки

«Сохранить картинку» открывает диалог с превью, переключателем размера и папкой; сохраняется ровно то, что видно в превью. Переключатель называет размер файла: «2400×1350 / 2160×2160 пикселей, PNG» (раскладки 1200×675 и 1080×1080, нарисованные вдвое крупнее, `MAP.pngSize`). На картинке строка с целью, типом пробы и окном (или «выделенный период»), карта с выносками, легендой и масштабом в виде по умолчанию, лента хопов (справа от карты в 1200×675, под ней в 1080×1080) и внизу подпись `Whilo Trace · IP Geolocation by DB-IP (db-ip.com), CC BY 4.0 · суша: Natural Earth`. Она всегда в темной теме, без пакета, табло, кнопок масштаба и выделенного хопа. Маскировка на ней включена всегда:

- Хопы вашей сети (уровень `own`: частные, CGNAT, loopback, link-local) и первые публичные хопы, пока не сменится номер AS, показаны как «скрыт», без имени и места, и нарисованы у дома. Хоп без номера AS смены не делает; если номера AS нет ни у одного из первых двух таких хопов, скрыты только эти два. Адреса прочих специальных диапазонов (их не ищут в базе, места у них нет), встреченные до конца ряда, скрыты вместе с ним и в эти два не входят; после ряда они остаются как есть. Ряд кончается на цели: цель вне вашей сети не скрывается, она и так в заголовке.
- Цель в AS скрытого ряда (например, DNS провайдера) и цель, которая сама первый публичный хоп (до нее только хопы вашей сети, специальные адреса и молчащие хопы: у провайдера внутренние адреса, VPN прямо до цели), оставляют адрес, но теряют имя, а их место сжимается до страны: точка подписи страны из `WT_COUNTRY_POINTS`, а если у страны такой точки нет, места нет. Цена: при VPN или молчащих хопах так показана и цель вне сети провайдера. В строке заголовка у такой цели и у цели из вашей сети нет второй подписи (обратного имени или адреса), а цель из вашей сети, набранная адресом, там «скрыт».
- Дом стоит в точке подписи страны дома (`trace.home.cc`). У дома, заданного вручную, страны нет: берется страна скрытых хопов; без страны или ее точки дом встает в точку подписи страны первого оставшегося места (города или страны), а в точку самого места, только если у его страны такой точки нет. Подпись у дома только «ваша сеть», без «(дом задан вручную)». Если у трассы дома нет, на картинке его тоже нет.
- Любой другой хоп и цель, чье место в городе дома, тоже показаны на уровне страны: точка подписи их страны, без города и имени, а у такой цели в заголовке нет второй подписи (роутер другого оператора в вашем городе или цель после хопов провайдера без номера AS иначе назвали бы город). Адрес у таких мест остается. «В городе дома» значит: та же страна и тот же город, что у автоматического дома, под любым из названий, которые DB-IP дает этому городу, или, для любого дома, не дальше 50 км от настоящей точки дома. У названия берутся формы: часть до района в скобках («Baku (Yasamal)»), город в последних скобках («Jinonice (Prague)»), часть после последней запятой («Ampelokipoi, Thessaloniki»), все без учета регистра и диакритики («Tehrān» и «Tehran», «Malmö» и «Malmo»); два названия считаются одним городом, если главная форма одного есть среди форм другого (у двух городов бывает район с одним именем: «Seattle (Downtown)» и «Los Angeles (Downtown)»); остальные написания и районы вида «A (Город)» и «B (Город)» покрывает радиус. Радиус нужен и автоматическому дому: части города DB-IP называет и отдельно, без названия города (в базе 2026-11 Khojasan и Badamdar лежат в 3 и 7 км от точки Баку). Поэтому соседние города ближе 50 км тоже показаны только страной (Sumqayit в 24 км от Баку). Слов «известна только страна» у таких мест нет: город база знает, он только скрыт. Это касается и цели в AS скрытого ряда.
- В выносках нет расстояний от дома: по двум таким расстояниям дом нашелся бы.

Карта в программе и карта в отчете для провайдера ничего не скрывают. Картинку пишет команда `save_image` в папку отчетов (`Документы\Whilo Trace`) или в выбранную кнопкой «Изменить…», под именем `whilo-trace-map-<цель>-<ГГГГММДД-ЧЧММСС>.png` (конец окна данных по местному времени; цель из вашей сети, набранная адресом, заменена на `route`; при совпадении `-2`, `-3`); потом «Открыть папку».

### Ограничения и что не проверено

- Точность Lite ниже: по таблице сравнения DB-IP индекс точности City Lite 77 против 96 у платной базы. Места роутеров часто неверны, проверка скоростью света ловит только грубые ошибки.
- Только IPv4, как и движок.
- Из программы к download.db-ip.com не ушло ни одного запроса: проверка и скачивание из программы проверены тестами на локальном HTTP-сервере. Не проверен ответ сервера на HEAD.
- `tools/fetch_geo.py` впервые скачал базы с db-ip.com в пробном запуске релизного workflow 2026-11-01: месяц 2026-11, `database_type` «DBIP-City-Lite» и «DBIP-ASN-Lite (compat=GeoLite2-ASN)». Тот же запуск собрал пакеты трех систем с `--config tauri.geo.conf.json`. Эти файлы открылись кодом программы (`files::pick`, `GeoDb`), поиск по ним проверен офлайн на десяти адресах: город, страна, координаты и AS (ключи `autonomous_system_number` и `autonomous_system_organization`) на месте. У 12 % записей с городом к названию добавлен район в скобках («Baku (Yasamal)»).
- Пакеты приложения с базой в пробной сборке 0.2.0: установщик Windows 47,5 МБ (у 0.1.0 3,2 МБ), portable zip 75,4 МБ (5,9), deb 74,1 МБ (4,5), dmg 76,6 МБ (8,6), AppImage 142,6 МБ (82,8). Распакованная база занимает около 130 МБ. Архивы командной строки ее не содержат.
- Unix-ветку локальной даты (`localtime_r`) для дней проверки собрали jobs `linux` и `macos` пробного запуска релиза 2026-11-01 (CI собирает приложение только на Windows, job `app`); на живых машинах она не запускалась.
- Карта проверялась в браузере на заглушке, в окне Tauri (WebView2) не проверялась, в том числе полноэкранный режим окна и остановка пакета в свернутом окне. Не проверено и то, гасит ли `preventDefault` на Ctrl + колесо собственный масштаб WebView2, как там приходят щипок тачпада и настоящие шаги колеса мыши.

## 11. Что не проверено и ограничения

- Linux и macOS бэкенды компилируются (`cargo check` под оба таргета), но не запускались на живых машинах.
- Нет IPv6, UDP/TCP-проб, алертов, комментариев на таймлайне, политики хранения.
- Установщики собирает workflow релизов (`.github/workflows/release.yml`, по метке `v*`): Windows: установщик NSIS для текущего пользователя без прав администратора и portable zip; Linux: deb и AppImage (сборка на Ubuntu 22.04); macOS: универсальный dmg. Файлы не подписаны, версия для macOS не нотаризована. Сборки для Linux и macOS вживую не проверялись.
- В окне программы не проверялись руками диалог выбора папки и «Открыть папку» (они открывают окна системы); перетаскивание проверялось синтетическими событиями.
- Карта маршрута: раздел 10, «Ограничения и что не проверено».
